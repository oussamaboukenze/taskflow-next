Q9 :
React SPA (Vite)
Routing : cote client avec React Router.
Data fetching : fetch/axios vers une API.
Mutations (CRUD) : appels HTTP vers un backend.
Auth : souvent geree via backend separe et stockage navigateur/cookies.
Base de donnees : via API Express ou autre backend.
Deploiement : frontend + backend separes.
SEO : plus limite sans SSR.
Performance : tres bonne apres chargement, mais bundle client plus important.
Nombre de projets : un projet frontend + souvent un projet backend.

Next.js Full-Stack
Routing : file-based routing dans app/.
Data fetching : Server Components, API Routes ou Server Actions.
Mutations (CRUD) : Server Actions et routes API.
Auth : cookies serveur.
Base de donnees : Prisma cote serveur.
Deploiement : un seul projet sur Vercel.
SEO : meilleur grace au rendu serveur et a la generation statique.
Performance : optimisations integrees avec next/image, next/font, SSG et streaming.
Nombre de projets : un seul projet full-stack.

Q10 : Pour une startup, Next.js full-stack est souvent un meilleur choix au depart : moins de projets a maintenir, SEO plus simple, backend integre, deploiement rapide et bonnes performances par defaut. React SPA + Express reste utile si l'architecture exige une API separee ou plusieurs clients.
